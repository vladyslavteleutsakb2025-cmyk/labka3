## Предметна область

Сервіс зберігає підсумки спрацювань засобів захисту за навчальні інтервали.

| Поле / сутність | Значення |
|-----------------|----------|
| Категорія (`categories`) | джерело спрацювання: `firewall`, `ids`, `antivirus` |
| `value` | **кількість спрацювань** — ціле число не менше 0 |
| Одиниця вимірювання | `events` (спрацювання за навчальний інтервал) |
| Поріг | **15 events** — навчальне значення, від якого активність вважається підвищеною (фільтр `min_value=15`) |
| `status` | стан перевірки підсумкового запису: `new`, `in_progress`, `done` |
| `code` | унікальний код запису за форматом `V05-NN` |
| `title` | назва запису: `Підсумок спрацювань NN` |

Таблиці `categories` і `records` пов'язані як «один до багатьох»; `ON DELETE RESTRICT`
забороняє видаляти категорію, у якій є записи. Значення навчальні й не описують
реальну інфраструктуру.

```
├── config.py        # одиниця вимірювання, поріг, обмеження варіанта
├── seed.py          # початкове заповнення бази з JSON

├── routers/
│   ├── categories.py
│   └── records.py
├── data/
│   ├── seed.json        # навчальні дані варіанта (у Git)

```

Розподіл відповідальності: маршрути обробляють HTTP, SQL міститься лише в
`repository.py`, моделі — в `schemas.py`, винятки SQLite перетворюються на HTTP-помилки в
`main.py`.

(Python 3.10+).

## Створення бази та початкове заповнення

```bash
python -m labs.lab03.database   # створити таблиці (повторний запуск безпечний)
python -m labs.lab03.seed       # 3 категорії та 8 записів в одній транзакції
```

Повторний `seed` для непорожньої бази друкує повідомлення й нічого не змінює.
Некоректний `seed.json` або порушення обмеження скасовує весь пакет.

Скинути базу: зупиніть сервер, видаліть `labs/lab03/data/lab3.sqlite3` і знову виконайте
`python -m labs.lab03.seed`.

## Запуск API

```bash
uvicorn labs.lab03.main:app --reload --host 127.0.0.1 --port 8000
```

* Swagger UI: <http://127.0.0.1:8000/docs>
* OpenAPI-схема: <http://127.0.0.1:8000/openapi.json>

Таблиці створюються під час запуску (lifespan); дані не перезаписуються й автоматично
не заповнюються.

## Маршрути

| Метод і маршрут | Призначення | Успіх | Помилки |
|-----------------|-------------|-------|---------|
| `GET /ping` | доступність API | 200 | — |
| `GET /student` | дані з `shared/student.py` | 200 | — |
| `GET /categories` | категорії за зростанням id | 200 | — |
| `POST /categories` | створити категорію | 201 | 409, 422 |
| `DELETE /categories/{category_id}` | видалити порожню категорію | 204 | 404, 409, 422 |
| `GET /records` | список із фільтрами | 200 | 422 |
| `GET /records/{record_id}` | один запис | 200 | 404, 422 |
| `POST /records` | створити запис | 201 | 404, 409, 422 |
| `PUT /records/{record_id}` | повна заміна змінюваних полів | 200 | 404, 409, 422 |
| `DELETE /records/{record_id}` | видалити запис | 204 | 404, 422 |
| `POST /records/bulk` | атомарне пакетне створення (1–100) | 201 | 404, 409, 422 |

Параметри `GET /records`: `category_id`, `status`, `min_value`, `q` (буквальний підрядок
у `title`, з урахуванням регістру), `limit` (1–100, типово 20), `offset` (≥ 0). Фільтри
поєднуються через AND, результат відсортовано за `id`.

## Приклади запитів (Bash)

```bash
curl -i "http://127.0.0.1:8000/ping"
curl -i "http://127.0.0.1:8000/student"
curl -i "http://127.0.0.1:8000/records?category_id=1&status=new&limit=5&offset=0"
curl -i "http://127.0.0.1:8000/records?min_value=15"

# створення (очікується 201, category_name = "firewall")
curl -i -X POST "http://127.0.0.1:8000/records" \
  -H "Content-Type: application/json" \
  -d '{"code":"V05-TEST","title":"Навчальний підсумок","category_id":1,"value":12,"status":"new"}'

# повна заміна (передати всі п'ять полів; підставте id з відповіді)
curl -i -X PUT "http://127.0.0.1:8000/records/9" \
  -H "Content-Type: application/json" \
  -d '{"code":"V05-TEST","title":"Оновлений підсумок","category_id":2,"value":20,"status":"in_progress"}'

curl -i -X DELETE "http://127.0.0.1:8000/records/9"

# скасування пакета: V05-01 уже є в базі -> 409, V05-ROLLBACK не зберігається
curl -i -X POST "http://127.0.0.1:8000/records/bulk" \
  -H "Content-Type: application/json" \
  -d '[{"code":"V05-ROLLBACK","title":"Перший елемент","category_id":1,"value":4,"status":"new"},{"code":"V05-01","title":"Дублікат коду","category_id":2,"value":5,"status":"new"}]'

# SQL-ін'єкція в пошуку обробляється як дані (200 і порожній список)
curl -i -G "http://127.0.0.1:8000/records" --data-urlencode "q=' OR 1=1 --"
```

У Windows ті самі запити можна виконати через Swagger UI.

## Рішення щодо перевірки даних і цілісності

* **SQL.** Усі значення передаються параметрами `?`; динамічні фільтри складаються лише
  з наперед заданих фрагментів, значення йдуть окремим списком. Пошук `q` використовує
  `instr(title, ?) > 0`, тому `%` та `_` не є шаблонами.
* **Pydantic.** `extra="forbid"` (зайві поля, зокрема `id`, дають 422), обрізання пробілів,
  довжини рядків, статус із набору `Literal`. `value` та `category_id` — `StrictInt`:
  `1.5`, `"7"`, `true` відхиляються. Верхня межа `2**63 − 1` (максимум `INTEGER` у SQLite)
  замінює потенційну помилку 500 на 422.
* **Транзакції.** Зміни виконуються всередині `with connection`; пакет додається однією
  транзакцією без окремих `commit()`. Після кожної операції з'єднання закривається;
  `PRAGMA foreign_keys = ON` вмикається для кожного нового з'єднання.
* **База як другий рубіж.** `CHECK`, `UNIQUE`, `FOREIGN KEY` у `schema.sql` діють незалежно
  від API.
* **Помилки.** `404` — немає запису чи категорії; `409` — дублікат `code`/назви або
  непорожня категорія; `422` — модель чи параметри. Технічні подробиці SQLite
  записуються через `logging`, клієнт бачить лише коротке повідомлення без SQL, шляхів і
  трасування (`500` — загальний текст).
* **Пакет.** Спершу перевіряються дублікати `code` всередині пакета (409), далі —
  існування категорій (404), потім вставка; будь-яка помилка скасовує весь пакет.
